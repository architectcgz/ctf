# 网络子网分配策略

> 状态：Current
> 事实源：`code/backend/internal/module/container_runtime/application/commands/provisioning_service.go`、`code/backend/internal/module/container_runtime/infrastructure/allocation_repository.go`、`code/backend/internal/config/`
> 替代：无

## 定位

本文档说明当前容器网络子网的动态分配、冲突检测、owner 复用和释放规则。

- 覆盖：单容器池、拓扑池、`network_allocations`、显式 subnet、shared network、Docker subnet conflict retry。
- 不覆盖：iptables / ACL 细则、AWD shared network 的业务可达性；容器安全和访问边界见 `docs/architecture/backend/03-container-architecture.md`。

## 当前设计

- `code/backend/internal/config/defaults.go`
  - 负责：提供两套默认地址池，单容器实例使用 `10.11.0.0/16` + `/29`，多容器 topology 使用 `10.10.0.0/16` + `/24`。
  - 不负责：把地址池暴露成 HTTP API 参数；请求只通过内部 `TopologyCreateRequest.SubnetPool` 表达分流。

- `code/backend/internal/module/practice/application/commands/runtime_container_create.go`
  - 负责：单容器题目构造 `SubnetPoolSingleContainer`，拓扑题目构造 `SubnetPoolTopology`；AWD stable contest network 会标记为 `Shared=true`。
  - 不负责：直接写 `network_allocations` 或查询 Docker 已占用子网。

- `code/backend/internal/module/container_runtime/application/commands/provisioning_service.go`
  - 负责：`allocateNetworkSubnet()` 对 `Shared=true` network 返回空 subnet，对显式 `network.Subnet` 原样使用；其他网络按 pool 走 repository 预留。
  - 负责：创建 network 前预读 runtime 当前占用子网，Docker 返回 `ErrRuntimeNetworkSubnetConflict` 且 network 是动态分配时，释放本次预留、把冲突 subnet 加入 excluded set，并继续尝试下一个候选。
  - 不负责：为显式 subnet 自动换段；显式 subnet 冲突代表调用方配置错误。

- `code/backend/internal/module/container_runtime/infrastructure/allocation_repository.go`
  - 负责：从 `subnetCandidates(baseCIDR, subnetMask)` 生成候选；`network_allocations.subnet` 作为主键，通过 `ON CONFLICT DO NOTHING` 在并发下抢占；带 `instanceID + networkKey` 的调用会优先复用 owner 既有 reservation。
  - 负责：`ReserveAvailableSubnetForInstanceExcluding()` 在 owner 既有 reservation 被 excluded 时，可通过 `moveSubnetAllocationForOwner()` 把该 owner reservation 移到新 subnet。
  - 不负责：判断业务实例何时释放；释放由 runtime cleanup / provisioning failure 调用。

## 边界

- 动态子网事实源是 PostgreSQL `network_allocations`，Docker 现状只作为冲突输入和创建结果。
- `Shared=true` network 不进入动态分配；AWD contest stable network 依赖同一 runtime node 的本地 Docker shared network 语义。
- 显式 `network.Subnet` 不进入动态分配和冲突重试；它由题包 / 内部调用方承担正确性。
- owner 复用只在 `OwnerInstanceID > 0` 且 `networkKey` 不为空时生效，避免重试期间同一实例同一网络反复占用新段。

## 接口或数据影响

- `network_allocations` 字段包括 `subnet`、`instance_id`、`network_key`、`created_at`、`updated_at`；`subnet` 是主键，`instance_id + network_key` 是 owner 唯一索引。
- `TopologyCreateRequest.SubnetPool` 当前只有 `single_container` 和 `topology` 两类内部取值。
- `InstanceRuntimeDetails.Networks[]` 会记录实际创建的 `network_id / name / subnet / shared`，但 shared network 的 `subnet` 可能为空。
- 地址池配置在启动时由 `code/backend/internal/config/` 校验 CIDR、网络地址、掩码和 overlap。
