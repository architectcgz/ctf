## Reason
这次不新增并行实现。`platform-users` 已经承担了用户治理之外的班级、学生目录和实例管理职责，适合把现有页面模型迁到更细的 feature owner 下，而不是继续往该桶里加代码。学生目录查询能力继续复用 `student-directory` 里的既有 query owner；平台侧的 `usePlatformStudentManagementPage` 只保留页面级筛选、分页和路由跳转编排，不再新造一条与 `useTeacherStudentManagementPage`、`useTeacherStudentAnalysisPage`、`useStudentListQuery` 平行的学生查询栈。继续收口 `/platform/classes/:className`、`/platform/classes/:className/students/:studentId` 与 `/platform/classes/:className/students/:studentId/review-archive` 时，也不复制一份 `TeacherClassStudents.vue`、`TeacherStudentAnalysis.vue`、`TeacherStudentReviewArchive.vue` 或对应 page hook；改为把实际 page workflow 上提到中性的 `class-students-workspace`、`student-analysis-workspace`、`student-review-archive-workspace` feature，再让 teacher / platform 各自保留 route view owner。平台班级工作台别名页也沿用同一模式：不保留 `platformRoutes.ts -> TeacherClassWorkspaceSection.vue` 的跨 namespace 依赖，不复制一份新的 panel redirect 逻辑，而是把 alias route 到 canonical workspace 的重定向 owner 上提到 `class-workspace-redirect`，让 teacher / platform 两侧 route view 都直接依赖同一个中性 redirect owner，不再额外保留 `teacher-class-workspace` 这层命名桥。`PlatformAwdReviewDetail` 也继续按相同思路处理：不保留 `platformRoutes.ts -> TeacherAWDReviewDetail.vue` 的直连，不额外复制一套 AWD detail widget 或导出流程，而是把页面级路由、轮次切换和返回索引 owner 上提到中性的 `awd-review-detail-workspace`，继续复用 `TeacherAWDReviewWorkspace` 和 `useTeacherAwdReviewExportFlow`，让 teacher 侧 detail hook 退成兼容桥。平台用户治理也沿用同样的收口策略：不删除 `platform-users` 的兼容入口，但把真实用户治理 owner 上提到更窄的 `platform-user-management`，继续复用现有用户 CRUD、导入、筛选和分页实现，让 `platform-users` 只作为历史桥而不再承载主实现。当前这刀的重点是 public API 边界，不新增平行 helper：`class-students-workspace`、`student-analysis-workspace`、`student-review-archive-workspace`、`awd-review-detail-workspace`、`teacher-class-report-export`、`teacher-student-review-workspace` 与 `teacher-review-archive` 继续复用 donor feature 里的既有 helper，只把 cross-feature `model/*` 深导入改成 donor feature 的公共出口，让边界测试真正开始约束“跨 feature 只能走 public API”。班级报告导出对话框也沿用同一模式：不复制 `TeacherClassReportExportDialog.vue`，不继续把 `useTeacherClassReportExport` 暴露成共享导出 hook，而是在现有 `teacher-class-report-export` 公共出口直接收口成中性的 `useClassReportExport`，让共享对话框通过同一个中性符号消费导出编排。班级学生页与学员分析页也沿用同一模式：不复制 `ClassStudentsPage.vue`、`StudentAnalysisPage.vue`，不保留 route view 继续直连 `components/teacher/class-management/*.vue` 路径，而是在 `components/class-management` 目录公共出口暴露中性页面壳，让 teacher / platform route view 统一通过同一个中性组件入口消费共享页面结构。学员分析里的介入推荐、复盘工作台和题解/人工评审流程也沿用同一模式：不新造平台侧并行 hook，也不继续把 `useTeacherInterventionRecommendations`、`useTeacherReviewWorkspace`、`useTeacherSubmissionReviewFlows` 暴露给共享页面或面板，而是在现有 `teacher-student-analysis` 公共出口直接收口成中性的 `useInterventionRecommendations`、`useReviewWorkspace` 与 `useSubmissionReviewFlows`，让共享学员分析相关 workflow 通过同一组中性符号消费介入建议、复盘证据、攻击会话和题解/人工评审流程。学员复盘工作台也沿用同一模式：不复制 `TeacherStudentReviewWorkspace.vue`，不保留 `TeacherStudentReviewWorkspace` 作为公共导出别名，而是在 `widgets/teacher-student-review-workspace` 公共出口只暴露中性 `StudentReviewWorkspace`，让 `StudentInsightAttackSessionsSection` 通过同一个中性符号消费共享复盘工作台。复盘归档 workspace 也沿用同一模式：不复制 `TeacherReviewArchiveWorkspace.vue`，不把 `TeacherReviewArchiveState`、`TeacherReviewArchiveSummarySection` 这类次级 teacher 组件继续暴露为公共 API，而是在 `widgets/teacher-review-archive` 公共出口只保留中性 `ReviewArchiveWorkspace`，让 teacher / platform route view 都通过同一个中性 workspace 入口消费共享归档页。班级洞察时间窗 helper 也沿用同一模式：不新造并行 date-range helper，也不继续把 `TeacherClassInsightWindow*` 暴露给 `class-students-workspace` 与 `teacher-class-report-export`，而是在现有 `teacher-class-insight-window` 公共出口直接收口成中性的 `ClassInsightWindow*` 符号，让共享 page workflow 和导出 workflow 都通过同一组中性 helper 消费时间窗语义。复盘归档 data owner 和错误消息 helper 也沿用同一模式：不新造并行 archive query 层，也不继续把 `useTeacherStudentReviewArchive`、`resolveTeacherStudentReviewArchiveErrorMessage` 与 `TEACHER_STUDENT_REVIEW_ARCHIVE_EXPORT_MESSAGES` 暴露给 `student-review-archive-workspace`，而是在现有 `teacher-student-review-archive` 公共出口直接收口成中性的 `useStudentReviewArchive`、`resolveStudentReviewArchiveErrorMessage` 与 `STUDENT_REVIEW_ARCHIVE_EXPORT_MESSAGES`，让共享归档页 workflow 通过同一组中性符号消费数据和导出状态文案。review 提示词也放到现有 `harness/prompts/` 目录，复用已有项目 prompt 资产形态，不新建额外 prompt 目录。当前继续处理 `request.ts` 的 P1-4 时，也沿用同一个原则：不再新造一层并行 request client、error gateway 或页面专用 transport wrapper，而是在现有 `request.ts` 上直接收缩 owner，让请求层只保留错误标准化、取消请求和 session 失效这类全局 transport 语义；`429` 与普通 `4xx/5xx` 的导航、toast、inline error、retry 政策继续交还给页面或 feature owner。继续处理 `P1-5` 时同样遵循单一 query owner：不新增 `platform instance` 专用 API，也不保留 teacher/platform 两套本地分页语义，而是直接把 `/teacher/instances` 收口成支持 `status/page/page_size` 和 summary 的分页 contract，再让 teacher / platform 两个页面一起复用这条 server-owned query。
